# How we curate

The list covers aardappel's Goose language. It borrows awesome-rust's browsable
categories, short descriptions, and community contribution model. It does not copy
Rust's category inventory into an ecosystem that cannot yet fill it.

## Admission

A project needs public source or first-party documentation, a clear Goose use case,
an identifiable license, and a usable entry point such as an API/example or install
guide. Describe what exists today. If a dependency or platform restriction materially
affects use, say so. Documented tests are supporting evidence, not tests we ran.

Small or prerelease projects can qualify. Stars, author affiliation, and the word
“awesome” in a description do not establish quality. Avoid unqualified claims such
as fastest, secure, production-ready, or fully compatible.

## Alternatives

Keep both when their ownership, deployment, API, or feature tradeoffs help a reader
choose. Explain important overlap in CHOICES.md. Prefer an upstream link to an
undifferentiated fork. Include owner names for collisions. List a project once in
its main category; cross-link its explanation where needed.

The maintainer also authors the carabistouflette libraries in this list. They use
the same inclusion criteria. Their presence is an affiliation disclosure, not a
reason to prefer them. Challenging an inclusion is welcome with source evidence.

## Evidence and upkeep

Record review date, public repository, immutable source link, and material limits.
README entries link to living upstreams; docs/sources.json records the reviewed
snapshot. Recheck descriptions when a package changes, when an issue reports stale
information, or before promoting a watchlist candidate. Remove broken or superseded
recommendations with a short reason in the change description.

Use Reddit for leads and community context. Confirm library features against the
project's own documentation/source before admitting it. If a search yields only
language discussion, record that limitation instead of inventing recommendations.

Search aliases capture equivalent task vocabulary. Recorded search cautions refer
to explicit limitations at the same reviewed pin. Matching those cautions stays
possible and is labeled in the directory; default grouped search puts these matches
after other results. Name/maintainer sorting retains the requested order. These
editorial search notes help discovery and do not certify compatibility or code.
