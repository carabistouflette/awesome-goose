# Directory UI review criteria

Review this directory as a tool for developers finding Goose libraries and resources.
Use direct rendered observation and interaction checks, supported by source inspection.
Evaluate the directory, its empty/filtered states, and at least one reading guide.

| Criterion | Weight | What to assess |
| --- | --- | --- |
| Visual clarity and typography | 20% | Readable text, hierarchy, contrast, spacing, restrained design |
| Discovery and information architecture | 25% | Finding a library, categories, useful density, identifying alternatives and limitations |
| Interaction and feedback | 20% | Search/filter combinations, reset, URL sharing, favorites, theme, clear active states and feedback |
| Responsive layout and accessibility | 25% | Mobile/desktop, keyboard, touch targets, labels, focus, semantics, long content and overflow |
| Content trust and consistency | 10% | Attribution, source/review evidence, honest limits, guide consistency, direct language |

Give each criterion a score from 0 to 10 and compute the weighted overall score.
For each issue, state observed behavior, impact, severity and a concrete recommendation.
State revision, tested viewports, flows checked and verification limits. Be candid;
ratings are subjective judgments. Do not change application code. Work independently
and do not read other review reports. Write only the requested report file.
