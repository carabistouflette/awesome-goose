# Independent FMHY UI assessment

Assessed live https://fmhy.net/ on 2026-11-06, approximately 14:41–14:49 UTC. Overall: **7.1/10** (7.075 before rounding). FMHY makes a very large directory usable through clear categories, section navigation and unusually capable search. Readability and accessibility details, plus the effort needed to compare entries, hold it back.

## Evidence behind scores

- **Visual clarity 7.0:** Restrained light backgrounds, consistent sans-serif typography, clear section hierarchy, large homepage category cards, generous reading spacing and coherent desktop columns make scanning straightforward. The desktop guide has a comfortable central reading width with a persistent category sidebar and separate contents rail. Many links are visibly pale blue; measured 16px content links are rgb(93,153,218) on rgb(248,250,252), approximately **2.85:1** contrast. Long slash-separated entries interrupt the otherwise calm layout.
- **Discovery / IA 7.5:** Homepage cards explain thirteen broad categories. Category pages offer active sidebar state, a nested contents rail/dropdown, emoji legend, recommendations and Starred/Indexes switches. Search for Project Gutenberg returned three grouped section matches with counts, highlighted matches and category chips (Books / Comics / Manga: 2; Android / iOS: 1). Public Domain is directly reachable through mobile contents navigation. The sampled Reading document contains **41 section headings and 1,261 anchors**, so navigation is useful but resource comparison still involves large amounts of reading. Homepage “Reading” becomes “Books / Comics / Manga”; “Streaming” becomes “Movies / TV / Anime,” which is understandable but adds translation effort.
- **Interaction / feedback 8.0:** Ctrl+K focused search; ArrowDown selected a result and Enter navigated to /reading#public-domain. Search supports exact/fuzzy and URL modes, category chips, detailed view, reset and keyboard hints. The zero-result state explicitly says No results for the query and offers Try fuzzy search. Escape closed search. Mobile section dropdown and sidebar opened successfully. Initial homepage prefetches returned HTTP 503 for several category chunks, but the search chunk/index loaded with 200 and direct category/guide navigation rendered. Do not interpret these transient errors as a confirmed broad outage.
- **Responsive / accessibility 6.0:** Homepage cards stack and text wraps at 390px; the mobile header gives Search and mobile navigation large labeled targets, while category pages expose separate Menu and On this page controls. At 320px, sidebar labels wrap and its long content scrolls. Main content had no material horizontal overflow in the 390px sample; the 320px document scrollWidth was 320px. Keyboard skip navigation receives an observable outline. However, two sidebar switches lack accessible names, several icon feedback controls are unnamed in the accessibility tree, the search overlay has an unusual role=button container around interactive descendants, and mobile search mode buttons measure only 32×32 CSS px (back/reset approximately 34×34). The 390px Reading document is roughly **41,805 CSS px** tall; its initial feedback callout consumes substantial first-screen space before the resource list.
- **Trust / consistency 7.0:** The homepage exposes a current November update, contribution route, repository revision link, community links and a no-hosting limitation; category pages offer Edit this page and feedback. Entries sometimes specify Account Required, Sign-Up, Requires Invite, platform requirements, status links or warnings; the guide supplies context and cautions. Public Domain is clearly separated. Many other entries have only a name, broad type and mirrors, without a visible per-entry checked date or reason for recommendation. This makes the star treatment more useful as a shortcut than as inspectable evidence.

## Severity-ranked findings

1. **High — Light-theme content links have insufficient contrast.** On Reading and Beginners Guide, sampled primary link color #5d99da against #f8fafc yields about 2.85:1 at 16px, below 4.5:1 for ordinary-sized text. These links are the directory's main task controls, so the issue recurs throughout browsing and search. Darken link text while retaining distinct hover, focus and selection treatments; verify all supplied themes.
2. **Medium — Unnamed controls weaken assistive-technology navigation.** Toggle Starred and Toggle Indexes are adjacent visible text but their role=switch buttons have neither aria-label nor aria-labelledby. Section feedback icons are also unnamed in the inspected accessibility tree. Explicitly connect each control to its visible label, and give section feedback controls a purpose and section name. The search input references an icon-only label and appears as an unnamed searchbox in the snapshot; verify its computed accessible name with assistive technology and supply explicit visible or programmatic text. Use proper dialog semantics for the search overlay instead of a button role containing nested interactive elements.
3. **Medium — Dense entries make choosing a resource harder than finding a section.** Reading contains 1,261 anchors, frequent slash-separated metadata and numeric mirror links such as 2/3/4. Unfamiliar names often have minimal descriptions; mirrors and supplementary tools can look like peer choices. Preserve dense expert browsing while adding consistent short descriptions, explicit mirror labels and a compact recommendation reason / last-checked field for featured entries. Keep existing contents and search shortcuts prominent.
4. **Medium — Mobile first-screen hierarchy delays directory use.** At 390×844, the homepage's large logo/hero pushes the category list down to about y=651; on Reading, a large feedback callout appears above Ebooks. A full Reading document is approximately 41,805px tall. Reduce mobile hero and feedback-callout height, put resource discovery first, and keep feedback available near section headings or after the initial resources.
5. **Low — Search mode controls are small and depend on symbols.** Mobile exact/fuzzy and URL buttons are 32×32, with = and a link icon conveying their function. Accessible state text and titles help, and zero-result recovery is good, but larger hit areas and a compact visible mode label would reduce touch and comprehension errors.
6. **Low — Featured-entry trust is hard to assess at the point of choice.** General update/revision and contribution mechanisms provide useful accountability, but sampled starred entries show no nearby selection rationale or entry-specific review date. Expose brief criteria and freshness where users choose a destination; retain stated requirements and warning notes.

## Limitations and tool behavior

The preview calls succeeded overall; no pair of same-step failures required an isolated Chromium fallback. One redundant Search click timed out with: “Preview automation click timed out after 15000ms. The click may have happened; check the page before retrying. \"button[aria-label='Search']\" still matches an element after the timeout.” Search was actually open after hydration. A category click attempted while that overlay was open also timed out, so direct own-tab navigation was used to continue. One guessed contents-button selector was absent and timed out; a fresh snapshot supplied the correct control and it worked. These automation timing/selector errors were not scored as site defects. Initial 503 prefetch failures are a reliability observation with limited reproducibility, not a scored finding. No workspace inspection or application edits were performed. The only file written is this report. Own review tab was closed after inspection.
