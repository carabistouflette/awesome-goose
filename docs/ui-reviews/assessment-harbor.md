# Harbor UI assessment

Reviewed revision **5f387aa**, 6 November 2026. This is an independent, subjective assessment against `CRITERIA.md`, focused on a developer finding and comparing Goose resources. No other UI review documents or Git history were consulted. No application files were changed.

## Scope and verification

- Inspected `site/index.html`, `site/app.js`, `site/style.css`, `site/catalog.mjs`, `site/theme.js`, the guide builder, and the Choice notes content.
- Used an owned preview tab on `http://localhost:8765/`. Confirmed live `innerWidth`/`innerHeight` of **1440 × 900** and **390 × 844** after resizing. A later 320 × 740 resize request still reported 390 × 844 in the page, so 320px behavior is **not verified**.
- Visually inspected separate headless Chromium screenshots of the directory in desktop list/cards, the mobile directory, and desktop/mobile Choice notes. These screenshots used an isolated temporary profile and the same local origin; they did not carry the preview tab's saved state.
- Checked list/card switching, SQLite search, `Databases` category plus `kaitk` maintainer, active chips and URL state, a no-match search, saved results and filtered saved-empty state, last-item removal, initial saved-empty recovery, save persistence across navigation, theme change/persistence, share feedback, source evidence, and `CHOICES.html#sqlite` with its return URL.
- Keyboard checks covered search typing, Escape clearing the query, Tab movement from search to its example controls, and a visible focus outline measured on the focused example. Native labels, button pressed states, live result status, and focus recovery after saved-item removal were also inspected.

Preview automation was unreliable: two image snapshots returned **“Preview automation snapshot timed out after 15000ms.”** Several clicks timed out or the browser disconnected; at least one category click applied later. These tool failures are not treated as application defects. For the remaining saved/reset/share/theme checks, controls were activated with DOM `.click()` in the owned tab and the resulting state was read directly. This verifies application handlers, not pointer hit testing or complete keyboard activation. Share reported successful copying; clipboard contents and denied-permission behavior were not independently exercised. Mobile screenshots used CSS viewport sizing, not a physical touch device. No screen reader, zoom, forced-colors, full link audit, external repository validation, or exhaustive guide/table audit was performed. The owned preview tab was closed.

## Ranked issues

1. **Medium — “Start here” is last in the default results.** Observed: the list starts with Command line and configuration, while compiler, documentation, packages, samples, and standard library appear after the other thirteen groups. Category navigation places Start here first. `browseOrder` in `site/app.js` explicitly moves it to the end. **Impact:** a newcomer browsing the primary content can miss the standard-library-first guidance and foundational resources; navigation and content order disagree. **Recommendation:** put Start here first in the default category order, or provide a compact introductory foundation block before third-party libraries.

2. **Medium, conditional/source-confirmed — Share fallback preserves a saved-only URL.** Observed in `site/app.js`: successful copying removes `saved` from a temporary URL, while the catch branch tells the user to copy the address-bar URL. In Saved, that address still contains `saved=1`. The successful toast was exercised; the failure branch was not forced. **Impact:** if clipboard access fails, the recipient can land in their own saved collection or an empty collection instead of the intended general filtered directory. **Recommendation:** show the already sanitized URL in a selectable fallback field, with the same explanation that saved items are excluded.

3. **Low — Mobile guide contents looks like a static heading.** Observed: the mobile Choice notes screenshot shows only “On this page” between horizontal rules. The closed native `summary` is styled with `display:flex` and has no explicit expansion icon, unlike the directory's “More filters +”. **Impact:** readers may overlook the topic navigation on a long guide. **Recommendation:** add a visible chevron or plus/minus and an “On this page” disclosure treatment consistent with More filters; retain native details semantics.

4. **Low — Some resources repeat the same guide destination.** Observed: the desktop logger row/card includes “Choosing a logger” within its description and a separate “Choice notes →” link below it; both point to the logging choice section. Equivalent duplication exists in other descriptions such as compression/TOML. **Impact:** repeated links add tab stops and visual noise without giving the reader a distinct action. **Recommendation:** retain one clearly named contextual guide link per entry, for example “Compare logging choices”, and remove the duplicate description link or generic footer link.

5. **Low — Mobile browsing has a substantial pre-result stack.** Observed in the 390 × 844 default screenshot: header, browse tabs, hero copy, search/examples, layout/share controls, and category controls place the first resource identity around y=590; only one full resource fits initially. **Impact:** browsing a category without a specific search requires early scrolling and gives little immediate sense of the catalog's density. The Results shortcut helps. **Recommendation:** modestly compress the mobile hero/control spacing or combine the results heading and layout actions, preserving readable text and 44px controls.
