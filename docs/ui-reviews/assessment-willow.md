Revision: `d7186d9`. Reviewed 2026-11-06 against `docs/ui-reviews/CRITERIA.md` only. Scores are subjective judgments based on the rendered directory and guide, supported by source inspection. No other review reports or Git history were read; application code was not changed.

## Ranked issues

1. **Medium — Desktop category changes retain an unrelated reading position.** At 1440×900, I scrolled the full directory to approximately 3000px and selected “Data formats and text” in the sticky sidebar. After rendering, `scrollY` was 724, the results heading was at −411px, and the first category heading at −254px. The first visible entry was goose-text, so the start of the nine-entry category was above the viewport. Readers can miss early alternatives and lose the filter/result context even though the sidebar updates correctly. On category or collection navigation, bring the new results heading into view below the sticky header, with an appropriate focus policy for keyboard activation. Preserve reading position for actions such as saving an item.

2. **Low — Same-day source baselines need an explicit relationship.** The directory's expanded HTTP evidence showed source snapshot `0fa7d19`, while `docs/COMPARISONS.md` pins carabistouflette/goose-http at `6dc7a98`. The config entry similarly uses `af77c28` in the directory/source inventory and `d296c68` in the comparison inventory. Both surfaces present 2026-11-06 review/research dates. The comparison does describe its pinned baseline, so this is a traceability ambiguity, not evidence that its feature claims are false. A reader following a choice explanation cannot immediately tell whether it covers the catalog's current snapshot. Identify the comparison's historical baseline and any later catalog refresh, or reconcile the pins and recheck affected claims. Link each explanation to the baseline it actually supports.

3. **Low — Changing resource layout closes expanded evidence.** I expanded “Source & review” on the filtered HTTP entry, then switched from List to Cards; the evidence disclosure was closed in the resulting card. `render()` rebuilds all entry nodes. Readers inspecting provenance have to reopen the same information when comparing layouts. Preserve disclosure state by resource ID across layout changes, or update layout styling without replacing the entry nodes.

4. **Low — Narrow comparison columns interrupt desktop scanning.** Near the end of the rendered comparison guide at 1440×900, the priority cell for “P3 / demand-driven” broke into several short fragments, including “dema”, “nd-”, and “driven”. This makes the priority column harder to skim despite ample width in the neighboring explanatory column. Give priority/status columns an intentional minimum width or shorten the visible label while retaining its meaning. Keep the successful mobile labeled-record treatment.

## Verification limits and browser handling

Preview discovery/status was followed by a new background tab on the dedicated `http://localhost:18876/` origin; only returned tab `tab_19_d5b76abc-f7a4-4854-98e0-1f423e6ab780` was operated. The first resize response briefly retained the previous viewport; a subsequent evaluation verified actual `innerWidth: 1440` before relying on the desktop view. Preview later intermittently reported “No preview automation host is available for select in environment f9086ae0-f4e4-45c7-9db4-0b9ce0132cf4.” Two consecutive Share clicks failed with the same error: “Preview automation click timed out after 15000ms. The click may have happened; check the page before retrying. \"#share\" still matches an element after the timeout.” Those failures are tooling limits, not scored application defects.

After those failures I closed my preview tab and used installed `/usr/bin/chromium` through installed puppeteer-core, with a dedicated temporary profile and browser instance. Each fallback instance was closed in `finally`; shared tabs and servers were left alone. Screenshots were inspected locally; no screenshot artifacts or application changes were added to the repository.

This is a representative browser review, not a WCAG certification. No screen reader, physical mobile device, browser zoom/text scaling, alternate browser engine, reduced-motion mode, offline/storage-denied environment, or exhaustive contrast measurement was tested. Back/forward history, operating-system theme changes, guide-return filter restoration, and every external link were not independently exercised. Upstream feature correctness, license validity, and remote commit contents were not re-audited; the trust score concerns the UI's attribution, disclosed method, limits, and internal consistency.
