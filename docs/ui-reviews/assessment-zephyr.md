# Awesome Goose UI assessment — Zephyr

Reviewed 2026-11-06 against `docs/ui-reviews/CRITERIA.md`, independently, without reading peer assessments or review history. Application revision: `443b4d8c474f88fe4f7463069ef9570788473ece`. Rendered frozen build: `http://localhost:18872/`.

The directory is a useful, readable developer tool. Concise descriptions distinguish similarly named packages, important limitations appear before following repository links, and filtering and saved states generally explain themselves well. The main shortcomings concern sorting and orientation during navigation rather than broken core flows. Scores below are subjective judgments of the observed build.

## Ranked issues

1. **Medium — Name A–Z sorts owner-prefixed labels instead of resource names.** At `/?sort=name`, the first twenty resources all belong to carabistouflette, ending with `honk`; `exaroth/coc-goose` and `kaitk/goose-acme` occur later. Someone scanning alphabetically for a package cannot rely on the selected order, and equivalent names stay separated by maintainer. `site/app.js:115` compares `a.label`, which includes the owner prefix. Sort this mode by `entry.name`, then owner as a tie-breaker; alternatively label the existing behavior “Repository A–Z.” Keep Maintainer as the explicit owner-first mode.

2. **Medium — Filtered result context is absent from the sticky toolbar.** With two SQLite matches, or one after combining maintainer/category, the prominent scope still reads “All 56.” The correct match count appears beside search and in group headings, but can scroll away; the overall filtered heading is visually hidden. This makes the visible total easy to mistake for the current result total, especially with several result groups. Show “2 matches” or “2 of 56” in the sticky bar, retaining the existing accessible heading and live status. Evidence: `site/index.html:36`, `site/style.css:305`, and `site/app.js:116`.

3. **Medium — Desktop keyboard access to search is unnecessarily long.** In the independent Chromium check, search was reached on the 23rd Tab press: header links, fourteen category buttons, contribution link, and introductory links precede it. The functional skip link targets `#directory`, after search; its next Tab reaches All. `/` works, and `aria-keyshortcuts` documents it programmatically, but the visible search hint does not reveal the shortcut. Add a “Skip to search” link or make the main skip destination include search, and display a compact shortcut hint. This is navigation friction, not a keyboard trap. Evidence: `site/index.html:15`, `:23`, `:32`, and `:35`.

4. **Low — Clear filters removes the focused control.** Activating the main Clear filters button with Enter resets the query successfully, then leaves `document.activeElement` on body because the now-disabled button is hidden. The next Tab reached Start here, so navigation remained possible, but the visible focus location disappeared immediately after the action. Restore focus to search or the result heading after resetting, as the empty-state recovery already does. Evidence: `site/app.js:135`, `:174`, `:192`, and `:196`; CSS hides disabled filter buttons.

5. **Low — Narrow category labels are cut off.** At 320×740, the collapsed Category select was about 150.5 pixels wide and displayed “Networking a” for “Networking and web (2).” At 375 pixels, an active Filters label similarly squeezed the selected category. Full active chips mitigate this after selection, and the native chooser exposes the options, but the main control cannot communicate its complete value or count. Reuse the short desktop category labels or allocate Category a full row when the neighboring Filters control grows. The page itself did not overflow. Evidence: mobile rendered observation and the mobile grid/select rules in `site/style.css`.

6. **Low — Start here conceals the most useful introductory choices by default.** Initial desktop and mobile views show only “Start here 5” and a plus, followed by third-party CLI packages. Opening it reveals the official package guide and the Standard library entry whose description explicitly says to check built-ins first. Beginners may select a dependency before noticing those resources. Expose a compact set of official links, open the disclosure on a first visit, or give the collapsed summary a descriptive preview such as “Official docs, packages, standard library.” Evidence: observed disclosure content and the default `false` at `site/app.js:161`.

## Source evidence and verification limits

Supporting source inspection was limited to application files: `site/index.html`, `site/app.js`, `site/catalog.mjs`, `site/style.css`, `site/theme.js`, the guide generator in `scripts/build-site.py`, and `docs/CHOICES.md`. For example, the rendered kaitk/goose-http disclosure exposed “Source reviewed 2026-11-06” and an immutable README URL pinned to `86fdeec31d911d4394d797a397660d6fed96ae5d`, plus Curation policy. Choice notes explicitly explain that directory pins and comparison baselines may differ. This establishes transparent attribution in the UI; it does not independently establish that every upstream claim is correct.

Preview status was checked first and a separate background tab was opened for this origin. Tooling intermittently reported **“Preview automation click timed out after 15000ms”** and **“No preview automation host is available for click”**. Status recovery allowed further preview checks. Later, repeated preview Tab/Escape requests reported success without the expected state changes. Remaining keyboard checks therefore used an isolated installed headless Chromium instance with its own temporary profile and real browser input events. Those checks confirmed functioning Tab, skip, search, Escape, and guide navigation. The preview failures are tooling limitations and were not scored as application defects. Ambiguous-selector errors were resolved with unique targets and likewise were not scored.

This was a representative visual/interaction review, not a full accessibility audit. No screen reader, physical touch device, browser zoom matrix, alternate browser engine, forced-colors mode, or storage-denied environment was tested. Screen-reader announcements are supported by inspected semantics, not verified speech output. Clipboard-success feedback was observed; clipboard contents and the denied-permission fallback were not independently exercised. The selected Choice notes guide has no tables, so comparison-table responsiveness is outside this review. External repositories were not comprehensively opened or revalidated, and no package performance, platform, or security claims were independently reproduced. Only the review report was written in the application repository; application code and shared servers were left unchanged.
